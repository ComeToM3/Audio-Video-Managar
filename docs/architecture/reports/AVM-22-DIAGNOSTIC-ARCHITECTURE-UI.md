# AVM-22 — Architecture UI et rationalisation du code produit

**Statut : diagnostic et recommandation uniquement.** Aucun code, test, configuration, donnée ou rapport antérieur n’a été modifié. Ce rapport est le seul livrable AVM-22.

## 1. Périmètre et faits de départ

- Les consignes `.github/copilot-instructions.md`, AVM-20 et AVM-21 ont été lues. AVM-21 impose de préserver le travail Git préexistant; le statut actuel reste très modifié, notamment dans les fonctions DVD, le wizard, la bibliothèque, le catalogue, le schéma SQLite, les tests et les rapports. Les modules existants et non commités ont été traités comme du travail utilisateur, pas comme des candidats au nettoyage.
- AVM-20 indique que `library_ui_mode="widgets"` était la configuration effective du poste. Elle n’a pas été relue dans les données locales pour ce mandat. Dans le code, la valeur par défaut de `AppConfig` reste `qml`.
- Le compte de 190 fichiers du paquet sur disque comprend 88 fichiers bytecode dans `__pycache__`. L’inventaire courant contient 87 fichiers Python source et 15 fichiers de ressources/documentation, soit 102 fichiers hors caches. Les bytecodes ne sont pas des composants à rationaliser.
- Une analyse AST en lecture seule a parcouru les 87 modules Python sans erreur de syntaxe; 84 sont atteignables par imports depuis `audio_video_manager.__main__`. Les trois modules hors de ce graphe sont détaillés en §4. La recherche d’appels, les imports dynamiques et les références QML ont été examinés séparément; le graphe AST seul n’est pas une preuve d’absence d’usage.
- La CI AVM-21 est la référence la plus récente : 369 tests, 14 groupes, tous réussis. Aucun test n’a été relancé pour AVM-22.

## 2. Widgets et QML

**Point architectural important :** l’application n’est pas une application QML. Le point d’entrée crée toujours `MainWindow` et son shell Qt Widgets; seule la vue Albums de `LibraryHost` peut être rendue avec `QQuickWidget`. Wizard CD/DVD, navigation principale, Historique, Paramètres et la nouvelle vue Vidéos/DVD restent en Widgets dans les deux modes.

| Critère | Bibliothèque Widgets (`LibraryPage`) | Bibliothèque QML (`LibraryPage.qml`) |
|---|---|---|
| Intégration et navigation | Page Albums native du shell; hébergée avec l’onglet Vidéos/DVD par `LibraryHost`. | Contenu imbriqué dans la même page Albums; ne remplace ni le shell ni les autres pages. L’onglet Vidéos/DVD reste un contrôle Widgets externe. |
| Fonctions visibles | Recherche, actualisation manuelle, ouverture de la racine et du dossier album, grille de pochettes, état de dossier manquant, informations album et table avec titres/durées/indication de piste manquante. | Recherche, grille, états « prêt/manquant », détail compact, nombre de pistes et ouverture du dossier album. Pas d’action d’actualisation ni d’ouverture de la racine; la liste des pistes n’est pas affichée (`compact: true`, liste de hauteur nulle). |
| Données | Lit le même catalogue et limite la liste à 500 albums; les pistes du détail sont chargées lors de la sélection. | Même catalogue/limite. Le pont prépare aussi les pistes de chaque album et recalcule une notion de « prêt » à partir des pistes. La règle Widgets « chemin album présent » et la règle QML « dossier et pistes présentes » ne sont donc pas équivalentes. |
| Comportement de mode | Toujours construit, y compris si QML est affiché; le mode Widgets est le repli automatique si le chargement QML échoue. | `AVM_LIBRARY_UI` (`qml`/`widgets`) prime sur la configuration; sinon `library_ui_mode`; valeur absente/invalide donne QML. Le changement enregistré dans Paramètres demande un redémarrage; le bouton de la bibliothèque bascule immédiatement sans enregistrer. |
| Stabilité | Chemin actif selon la configuration utilisateur constatée dans AVM-20; pas de moteur Qt Quick à démarrer/arrêter. | AVM-08B rapporte une capture Windows où QML est effectivement actif et un repli explicite. Le chargement gère les erreurs; l’arrêt ordonné du `QQuickWidget` et du pont est requis et couvert par AVM-10C.1. Les tests offscreen ne démontrent pas à eux seuls le rendu Windows actuel. |
| UX et accessibilité | Présentation plus dense et moins illustrative, avec davantage d’informations directement inspectables. Les contrôles natifs et noms accessibles sont présents. | Grille visuellement plus travaillée et adaptative; noms accessibles, rôle bouton et action press existent. Le rapport AVM-08B classe encore l’audit NVDA comme risque à traiter; aucune parité lecteur d’écran n’est démontrée ici. |
| Coût de maintenance | Une seule implémentation Albums, déjà utilisée par les vues/widgets et tests. | Deuxième implémentation avec pont/modèle, six fichiers QML et `qmldir`, logique de recherche/pochettes/état répétée, configuration, sélecteur, bascule et chemin de teardown Qt Quick. Les ressources QML sont empaquetées par `pyproject.toml`. |

### Recommandation principale

**Retenir Widgets comme bibliothèque principale AVM-CD 1.0; conserver le shell Qt Widgets.** C’est la seule voie déjà active sur le poste selon AVM-20, elle expose l’information piste par piste plus utile pour contrôler une collection, et elle évite d’imposer la maintenance Qt Quick pour un gain essentiellement visuel. Aucun manque fonctionnel bloquant n’a été démontré dans le chemin Widgets par l’inspection statique.

**QML : conserver temporairement dans le dépôt, sans nouvel investissement ni statut d’interface principale.** Ne pas le supprimer avant décision produit : il a une preuve Windows historique, une expérience visuelle distincte et des utilisateurs pourraient avoir une configuration explicite QML. Pour une V1 à interface unique, une décision ultérieure devra retirer l’accès QML du parcours publié, puis décider séparément de supprimer son implémentation. Ce mandat ne change pas le défaut `qml` ni les configurations.

## 5. Risques à suivre dans le travail non commité

- Le nouvel onglet « Vidéos / audio DVD » est extérieur au choix Albums Widgets/QML. Il fonctionne donc conceptuellement avec les deux rendus; aucune migration du DVD vers QML n’est nécessaire.
- Dans le diff courant, le libellé et le bouton de bascule Albums restent visibles quel que soit l’onglet média. Quand l’onglet Vidéos est sélectionné, le bouton agit sur la pile Albums cachée et ne change pas la page visible. C’est une incohérence d’interaction déduite du câblage statique de `LibraryHost`, pas un résultat observé en exécution; à traiter avec la fonctionnalité DVD déjà en cours, sans modifier ce travail dans AVM-22.
- Les tests existants couvrent les deux chemins à des niveaux différents : `test_library_qml_08b.py` a cinq tests de mode/pont/repli; `test_qt_teardown_10c1.py` vérifie les références QML au teardown; `test_qt_teardown_10c2.py` construit aussi le mode QML mais valide surtout le nettoyage général. Les tests Widgets couvrent grille, recherche, état vide, album manquant, détail et navigation. La capture Windows AVM-08B est une preuve historique; elle ne valide pas les modifications UI DVD non commitées actuelles.

## 6. Plan de simplification minimal

1. **Décision produit : confirmer Widgets comme interface principale CD 1.0.** Si confirmé, aligner dans un changement ciblé les nouveaux défauts sur Widgets et garder QML uniquement comme option transitoire explicitement identifiée; ne pas modifier la configuration personnelle ni forcer une migration. Préserver `LibraryHost`, l’onglet DVD, `LibraryPage` et tous les parcours existants.
2. **Après période de validation et confirmation qu’aucun utilisateur ne dépend de QML :** retirer de façon coordonnée le rendu QML Albums, `LibraryBridge`, les six fichiers `.qml` et `qmldir`, le chargement QML du `LibraryHost`, les ressources QML de `pyproject.toml`, puis la sélection/bascule QML (`library_ui_mode`, Paramètres et `AVM_LIBRARY_UI`). Adapter les cinq tests QML et le test de teardown spécifique; conserver les protections Qt générales et tous les tests Widgets/DVD. C’est le retrait à meilleure valeur de maintenance, mais le risque porte sur les configurations QML existantes et l’UX visuelle.
3. **Séparément, après choix explicite sur `DiscMetadataDialog` :** soit l’intégrer réellement au parcours choisi, soit retirer son code non branché et ses trois tests; mettre à jour uniquement la documentation de référence encore présentée comme actuelle. Garder les services CD partagés. Ne pas faire cette opération pendant que les modifications AVM-19 du fichier restent non résolues.
4. **Ne pas ouvrir de chantier pour `PlaceholderPage` ou `metadata/factories.py`.** Le premier est retirable mais négligeable; le second reste utile à l’outillage de test. N’effectuer aucune consolidation supplémentaire par préférence de style.

### Impact estimé sur la suite existante

La base de comparaison est **369 tests / 14 groupes** du rapport AVM-21, non relancée ici. Le retrait QML touche directement les cinq tests de `test_library_qml_08b.py` et le test QML de teardown 10C.1; le test 10C.2 et les fixtures Qt nécessitent une adaptation ciblée, pas une suppression automatique. Les suites Widgets, CD et DVD restent requises. Une décision sur le dialogue touche ses trois tests dédiés. `PlaceholderPage` n’a aucun test référencé.

## 7. Approbations requises et arrêt

1. Confirmer ou non **Widgets comme seule interface principale AVM-CD 1.0**, avec QML conservé provisoirement en option puis retiré après validation.
2. Décider du sort produit de **`DiscMetadataDialog`** : parcours à intégrer ou parcours abandonné; aucune suppression avant cette décision et la résolution de ses changements non commités.
3. Confirmer que l’état d’intégration de la nouvelle bibliothèque DVD présente dans les modifications locales est bien celui à préserver; le point de bascule visible sur l’onglet Vidéos devra être considéré avant livraison.

**Aucun retrait, désactivation, test, modification de configuration ou refactoring n’a été effectué. Arrêt AVM-22 en attente de décision.**
